# D-234 机翻的重复回声是解码缺陷，护栏要三层：参数 + 折叠 + 密度截断

- 日期：2026-10-25 · 状态：已采纳

## 结论

Opus-MT（ct2）的字幕译文出现「正在 正在 正在」「看不见看不见…」这类重复，
**不是素材脏、也不是清洗链拼接**，是解码退化。修在翻译引擎出口，三层：
`no_repeat_ngram_size=3 + repetition_penalty=1.5` 为正解，
`_collapse_repetition`（精确循环折叠）与 `_trim_degenerate`（密度截断）为兜底。

## 背景

2026-10-25 用户报「翻译出来的字幕有很多冗余是重复的中文短语」。取
`data/output/pipeline/2026-10-19-08/subs.ass` 现场：单条字幕 800+ 字，
「正在」连出 120 次、「看不见」连出 200 次。逐步剥离定位：

- ASR 源文（`asr.srt`）干净 → 不是转写问题；
- `translate_batch_local` 的**原始返回值**就已经重复 → 不是清洗链、不是拼接；
- 11 条源文（端到端判据里那批，5 条退化 + 6 条正常）在 ct2 默认参数下
  **10/11 超标**（循环正则命中或密度 ≥0.35），连「He walked into the
  kitchen…」的正常译文都在复读——这不是边角料；
- `compute_type` 不是元凶（float32 默认反而 4/5 退化）；
- ct2 默认 `max_decoding_length=256` 是硬顶，长输出被截在循环中途（实测
  1012 字源文止步 428 字、结尾没有收尾标点）——截断发生在解码中途，调用方
  分辨不出「译完了」和「被顶断了」。

定标（ct2 4.8.1 / int8 / beam=2，同一批 11 条源文，`nrn=3 + disable_unk`
打底）：`rp=1.25 → 2/11 超标`、`rp=1.3 → 1/11`、**`rp=1.5 → 0/11`**；
`nrn=3` 单用仍有密度 2.00 的近似回声，`rp≤1.2` 单用基本无效。实测密度分布：
手写正常句 0.000、真实机翻中等输出 0.314、事故样本折叠后最低 1.600——
**阈值 0.35 是夹在两族之间量出来的**。

## 选项与取舍

- **选了**：三层。参数是正解，但它是对**这批样本**的定标——换个输入仍可能
  退化（用户报的就是没在我们样本里的输入），所以兜底不能省。
- **没选**「只修清洗链去重」：循环产自引擎，清洗链拿到的已经是重复文本；
  而且字幕路径走 `clean_zh_subtitle_text`、旁白路径走 `_clean_translation_text`，
  两处各修一遍必然漂移——护栏放引擎出口，两条路一起覆盖。
- **没选**「直接丢弃疑似退化的整条译文」：退化文本里常混着可用内容，
  截到最长干净前缀比整条丢掉损失小；整条丢弃会让字幕空掉。
- **没选**「换模型 / 上 API」：D-189 已定去 API 化，本地引擎的质量问题
  在解码层解决。

## 判据

- `tests/test_translate_engine.py`（13 条），五组成对变异实测打红：
  - 参数退回 ct2 默认 → 1 red（接线守卫）
  - 折叠变空操作 → 1 red（事故现场链路）
  - 阈值调高到 10（门不开）→ 3 red
  - 阈值调低到 0.30（误伤真实机翻 0.314）→ 2 red
  - 密度不再排除同字 gram → 1 red
- 端到端一条跑真实模型（`repo_data_dir` 把 `data_dir` 指回仓库 `data/`，
  否则 conftest 的临时目录让 `local_mt_ready()` 恒 False、判据永远跳过）。

## 代价

- 三层里有两层是兜底，正常路径永远走不到——它们的价值只在「下一批输入」
  上兑现，平时看起来是死代码（用变异对照证明它们不是）。
- `repetition_penalty=1.5` 对**正常**译文也有影响（个别词序变化），实测
  不劣于原输出，但这是黑箱，没有逐句人工比对。
- 密度阈值 0.35 依赖当前模型的输出分布；换模型后必须重测两族分布。

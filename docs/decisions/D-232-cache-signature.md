# D-232 判「内容变没变」要判内容，`.size` 不是内容

- 日期：2026-10-17 · 状态：已采纳

## 结论

宿主判断「这次渲染结果与上次是否相同」必须比较**内容**，不能比较数量。画布改用 `mermaidCacheSignature()`（排序后的 `键:SVG长度` 串），并加一条源码级守卫防止退回 `cache.size`。

## 背景

Mermaid 预渲染 cache 的键是**源码内容的哈希**（`mermaidKeyOf`，D-229）。于是「块数没变」与「内容没变」是两件事：改一张图里的一个字，块数不变而键变了。

原实现比较 `cache.size` → state 被判成「没变」而交回旧引用 → **旧 SVG 一直挂在画布上**。用户看到的症状是「编辑 mermaid 偶尔不响应」，得删掉另一张图或重开页面才生效。

## 选项与取舍

| 选项 | 评价 |
|---|---|
| **新增 `mermaidCacheSignature()`：排序后的 `键:SVG长度`** | 采纳。排序让「同一批图换了位置」不算变化（Map 插入顺序跟文档顺序走）；带长度兜住「源码没变、主题变了」 |
| 直接比较 SVG 全文 | 否决：栅格化后那是一张 dataURL，每敲一键把所有图的全文拼一遍纯属浪费 |
| 只比较键集合 | 否决：主题切换时源码没变而 SVG 变了，键集合完全相同 → 换深浅主题后画布不更新 |
| 每次都换新引用（去掉判同） | 否决：那正是 PerfBudget 判据当初抓到的回归（每敲一键多触发一次重排，6 次 vs 预算 2 次）。**「引用稳定」与「内容变了要换引用」是两条同时为真的要求** |

同源码同长度的两张不同 SVG 在视觉上无差别，这个盲区是可接受的交换——用一次肉眼不可见的边界，换掉每敲一键的全量拼接。

## 判据

- `packages/mdcore/src/theme/mermaid.test.ts`（6 条）—— 钉住签名语义：块数同内容异 / 顺序变 / 重复取稳定 / 同键不同长 / 空值 / 同键去重。
- `frontend/src/pages/mdstudio/AsyncRenderWiring.test.tsx`（1 条源码级守卫）—— 断言 `CanvasPanel.tsx` 用了 `mermaidCacheSignature`，且不出现 `sameCache = prev.cache?.size`。
- 成对变异：宿主改回比 `size` → 1 red；签名丢掉长度 → 1 red；签名退化成 `String(size)` → 2 red。

## 代价

- 多一个纯函数（mdcore 导出，签名 `mermaidCacheSignature(cache?)`）。
- 「同键同长不同图」检测不到。要收紧就得比全文，代价是每敲一键拼所有 SVG——**明确不划算**。

## 沉淀

1. **注释是最容易骗人的文档**：它写意图，代码写事实。原代码上方 5 行写着「内容没变就交回同一个引用」，而代码比的是数量——读注释的人（包括我自己）会以为这事已经做对了。**注释声称的语义本身值得一条判据。**
2. **jsdom 里 mermaid 必失败 → cache 恒为空**，所以「改图之后画布换没换引用」在组件测试里根本观测不到。这时判据要**守接线本身**（源码级守卫），别去演一个演不出来的状态。
3. **一条只测「没多触发重排」的守卫会给「永不更新」发通行证**——两条要求必须分别表达。

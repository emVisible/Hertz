## 0. 本次修复（已完成）

**现象**：工坊里保存提示「保存失败，请检查后端」，删除点了没反应。后端 500：
`asyncpg UndefinedColumnError: column layout_revisions.updated_at does not exist`。

**根因**：`LayoutRevision` 继承 `BaseModel`（声明 `updated_at`），`wave10_layout_data_safety`
手写建表 SQL 只给了 `created_at`。ORM 的 INSERT 带 `RETURNING updated_at` → 库里没这列 →
每次 PUT（快照改前内容）与 DELETE（删除前也要快照）都 500。**测试没拦住的原因**：测试库
schema 由 `create_all` 从**模型**重建，永远带着这列；只有走 alembic 的库才缺——
两条建 schema 路径分叉（AXIOM §22.1 口径的漂移）。

**修法**：新迁移 `wave34_layout_revisions_updated`（接在 wave10 之后，heads 仍为 2），
加列并回填 `created_at`（快照落盘后不会再改，两列本就同值；不把存量行抹成迁移执行时间）。

**验证读数**（全部真跑过）：

| 检查 | 结果 |
| --- | --- |
| 真机 API 全路径 | create 200 → PUT 200 → revisions 有 seq=1 → DELETE 200 → GET 404 → 回收站可见 → restore 200 → 回版 200 → purge 200 |
| pytest | 56 条过（test_layout 25 + migration_bootstrap + board_domain heads 守卫） |
| `alembic check` | `layout_revisions.updated_at` 的 add_column 漂移消失（其余为存量反映噪音，见 §4-E2） |
| 新增守卫 | `test_revision_ids_fit_alembic_version_column`——alembic 自建 `alembic_version.version_num` 是 VARCHAR(32)，超长 id 会让整条迁移在最后一步 UPDATE 时回滚（本迁移第一版 33 字符实测踩中） |

**结构性教训**（写进清单 §4-E1）：测试库与迁移库各建一套 schema，"模型加了列、迁移没加"
这类漂移在测试里**永远绿**。这次是运气好——只有一个列；同一条路上任何手写迁移漏列都会
以同样的方式炸在用户脸上。

## 4. 更新清单

排序原则：先"发不出去/不敢发"（合规、发布链路），再观感，再生态。每条都写了判据——
按本仓惯例，判据必须被"拿掉修复"的成对变异打红过才算数。

### P0 — 发布前合规（对小红书命理类内容是刚需）

**P0-1 违禁词/敏感词检测（接入诊断横幅）**

- 依据：壹伴 5 类违规 + 18 种隐蔽风险、135 合规中心（多行业词库+自定义）都被验证是
  差异化卖点；Reditor 靠违禁词检测在小红书场景立足。**对本用户的直接依据**：小红书
  命理文化号，2026 平台玄学治理红线是内容生命线——发布前自查是日常动作，不是可选项。
- 落点：**复用画布诊断横幅**（已有界面槽位，零新 UI 范式）+ 画布内命中块高亮 + 列表
  计数。词表驱动，两层：通用 5 类（暴恐/色情/政治敏感/低俗辱骂/低质灌水）+ **命理/
  玄学专属词表**（符咒、改运、通灵、破灾类话术——正是治理红线盯的那批）。
- 规则面：谐音/变体规则（拼音首字母、拆字、间隔符插入）按壹伴口径做第一版子集；
  误报走白名单（逐条可豁免，白名单随稿存 cover 槽——加键不需要迁移）。
- 判据：①成对变异——删掉词表装载，命中断言红；②命理专属词表每词一条红测；
  ③白名单豁免后同词不再报；④**无命中时横幅完全不出现**（正常稿件零噪声，与现有
  诊断横幅同纪律）。
- 工作量：词表+规则引擎 ≈2–3 天；横幅接线+高亮 ≈1 天。总 ≈3–4 天。
- **状态（2026-10-16）：已完成。** mdcore 两层词表 + 扫描引擎（9 项单测绿）+ CanvasPanel 接线 + 合规横幅 6 条判据；`frontend/src/test/setup.ts` 顶部 `NODE_ENV='test'` + 预热 React（`act is not a function` 修复，`npx vitest` 恢复可用）。第二轮复核补齐两处「说支持、产物里不成立」：①宿主忽略过滤误用 `matched`（逃逸原文）→ 改按 `term`（词表原形），`ComplianceIgnore.test.tsx` 3 条判据守宿主层（过滤字段/落库/读回各自成对变异打红）；②白名单从会话内状态改为随稿落库 `cover.compliance_whitelist`（刷新/换稿仍豁免）。合规文案 10 个 key 的 `en.json` 补英文。mdcore 376 / 前端 371 全绿。

**P0-2 Electron 里走通四个导出按钮（验收腿，非开发）**

- 依据：`HANDOVER_MD_STUDIO.md` §6——自动化浏览器证不到宿主剪贴板权限与另存路径；
  §4 记的 7 个坑里 3 个只有真浏览器抓得到。本次漂移 bug 也说明"结构层全绿"不等于

- 判据：四个按钮各产出合法字节（PNG 魔数/ZIP 头/剪贴板 text/html 可粘）。
- 工作量：0.5 天（人工）。

### P1 — 发布链路与观感

**P1-1 图床（公众号带图长文的发布前置）**

- 依据：mdnice 自建图床、doocs 13 种（含公众号 appID+appsecret）、Md2All 公式转图自动
  上传——三家全都做；公众号要求图片在微信图床是硬约束。我们现状：正文图片 dataURL/
  同源，二维码存 `cover.qr`（200KB 上限）。XHS 路径不受影响（snapdom 已栅格化进卡片），
  **缺口只在微信富文本粘贴这一条路**。
- 方案 A（直发路线）：公众号图床上传（appID/appsecret，凭证进 settings 不进稿）。
- 方案 B（零后端兜底，huasheng_editor 路线）：粘贴图→Canvas 压缩→IndexedDB→复制时
  Base64。本机导出/复制不受云依赖，与"本地优先"定位一致。
- 建议 A+B 都留：A 给"真要发公众号"的人，B 给默认路径。
- 判据：上传成功/失败两条路径；失败时图仍以原形态进产物（降级不炸）；凭证不明文落库。
- 工作量：≈3–5 天（A 为主）。
- 前置：P0-2 先确认真实粘贴时 dataURL 图片到底会不会被公众号编辑器接受——可能 B 就够。

**P1-2 公式在公众号的落地（KaTeX 字体问题）**

- 依据：mdnice 用 MathJax→去 `<defs>` 的 SVG、Md2All 转图片+图床，两条成熟路线都在
  解同一个问题——**公众号清洗器剥 `@font-face`**。我们现状：KaTeX 走 CSS+字体，微信
  适配器只有 MathJax 遗留规则（`mjx-container`→section），**KaTeX 在公众号粘贴路径上
  的字体落地没有对应处理**（XHS 卡片栅格化没问题）。
- 判据：真浏览器粘贴验收（与 P0-2 同一次走）；结构层先补 `data-mdcore-formula-tex`
  契约在微信产物里的保真断言。
- 工作量：≈2 天（+ 验收）。
- 前置：P0-2。**先验再决定做 SVG 还是转图**——可能结论是"转图"，那与 P1-1 合并做。
- **状态（2026-10-16）：结构层已完成；真机验收待 P0-2。** `stripUnsafe` 对 `data-mdcore-formula-tex` 开例外——它不是编辑器状态，是公式在平台产物里的数据契约（公众号清洗器剥 @font-face，落地方案与验收都要靠它在产物里认出公式、取回原始 TeX）；其余 `data-mdcore-*` 标记照旧剥。保真断言在 `theme/formula.test.ts`（行内+块级两条 TeX 保真、编辑器标记仍不出现）。成对变异：注释掉例外 → 断言红，恢复 → 绿（实测过）。

**P1-3 Shiki 二次 pass 高亮**

- 依据：§10 原候选第 3 条；Md2All 80+ 代码主题、doocs 自定义主题色说明代码观感是
  被反复投资的位点。我们的 hljs 40 类色映射是"能用"，Shiki 的 token 精度是"好看"。
- 判据：13 张基线图中含代码样例的那几张逐像素比对 + 成对变异（回退 hljs→红）。
- 工作量：≈2–3 天。
- 前置：无。可与 P1-2 并行。

**P1-4 稿件列表搜索与管理**

- 依据：mdnice 有文件管理+历史；我们的列表面板无搜索（代码核实过）。稿件量上来后
  这是每天都会撞到的摩擦。秀米/135 的"模板库检索"同理。
- 判据：搜索命中/空结果/大小写；与现有 selected 态不互斥。
- 工作量：≈1 天。便宜，随时可插入。
- **状态（2026-10-16）：已完成。** `LayoutListPanel` 按稿名过滤（大小写不敏感、空结果
  明确提示、Esc 清空）；判据 5 条红测在 `ListSearch.test.tsx`（命中/大小写/空结果/清空
  恢复/与选中态不互斥）。写测试时抓到一个真 bug 并修掉：**点击已选中的稿行会把画布清空**
  （清 draft 后 effect 依赖未变、不会重载，`MdStudioPage.tsx` onSelect 短路修复）。

**P1-5 核实项：代码高亮主题是否用户可选**

- 现状不明：设计器有代码槽，但"7 套代码主题切换"（mdnice 口径）在我们这里是否等价
  于 token 调色，需读 `themeDesigner/schema.ts` 确认。若 token 已覆盖→降为 P2 文档澄清；
  若无独立主题集→按 Md2All 口径补 5–8 套预设。
- 工作量：0.5 天核实。
- **状态（2026-10-16）：已核实——无独立主题集。** 设计器代码分区只有结构项（`codeBar`：
  mac 条/语言标签/无）与底色字色（`codeBg`/`codeInk`/`codeSize`/`codeLineHeight`/`fontMono`）；
  hljs 40 类 token 色是主题里的**固定浅深两套字典**（`hljsLight`/`hljsDark`），无用户可选集。
  补预设的动作**并入 P1-3 一起评估**（Shiki 二次 pass 会重做这层色映射，先做 hljs 预设
  有返工风险）；在 P1-3 落地前先在文档承认这一条目缺失。

**E1 迁移漂移看守测试（建议 P0 级，最便宜）**

- 问题：测试库 `create_all` 从模型建 schema，迁移库走 alembic——两套真相源，漂移在
  测试里永远绿。本次 `updated_at` 漏列即此类；`hertz_drift_check` 库的存在说明这个坑
  已经被手工踩过。
- 做法：新增一条测试——起一个全新库，`alembic upgrade heads`，再跑 autogenerate 比对，
  **断言不存在 add_column / remove_column**（这两类是唯一会让 ORM 在运行时炸的漂移；
  modify_nullable、JSON→JSONB 之类存量噪音不进断言，见 E2）。
- 判据：成对变异——从任意迁移里删一列，该测试红。
- 工作量：≈1 天。**性价比全场最高**：一类"用户脸上炸"的 bug 从此有自动看守。
- **状态（2026-10-16）：已完成。** `backend/infrastructure/drift.py`（口径唯一实现：
  结构类 = add/remove table/column，其余降级为计数）+ `tests/test_migration_drift.py`
  （`hertz_drift_guard` 全新库 → 全量迁移 → 比对断言）。复核：空库比对报 36 处结构漂移

  实测过，模块 docstring 有记录。

**E2 漂移检查口径固化**

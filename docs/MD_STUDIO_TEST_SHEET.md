## 1. 三段测试稿（直接复制粘贴）

稿子取自 `packages/mdcore/fixtures/typography.ts`——就是基线图用的那份，所以你在屏幕上
看到的应该和基线图一致。**有明显不同就是缺陷**，请贴回来。

### 稿 A：长文（微信 / 知乎都适用）

```markdown
# 把设计判断写下来

[toc]

这一节讲**为什么**要这样排，而不是讲怎么实现。先说结论，再给理由。

## 三条取舍

1. 标题只加一种装饰
2. 序号与正文分色
3. 段距用 em 而不是 px

> 排版的第一原则是层级可读。装饰越多，层级反而越难读——因为每一种装饰都在喊。

> [!TIP]
> 正文里的强调优先用 ==荧光笔==，而不是把整句加粗——加粗会让中文笔画糊成团。

- [x] 已完成：结构一处作者
- [ ] 未完成：主题只写性格 :sparkles:

重点在[color:#c2410c]层级可读[/color]，不在装饰数量。

| 层级 | 字号 | 装饰 |
| :--- | :---: | ---: |
| h1 | 1.7em | 一种 |
| h2 | 1.4em | 一种 |
| h3 | 1.18em | 一种 |

行内公式 $E = mc^2$、与[color:#c2410c]彩色文字[/color]混排。

$$\frac{a}{b} = c$$

```ts title="rhythm.ts"
const spacing = "0.62em"; // 改字号时它跟着缩放
if (spacing) { paint(theme) }
```

### 关于中文正文

中文字间距用 em 级的小值（0.02em 上下）比 letter-spacing: normal 更稳。

---

## 小结

- 结构一处作者，主题只写性格
- 装饰必须是真元素
- 节奏用 em

#排版实践 #中文写作
```

### 稿 B：短文卡片

```markdown
# 三件今天就能做的小事

把排版当产品做，而不是当模板选。

1. **先定层级**，再挑装饰
2. 段落间距跟着字号走
3. 一次只改一件事，改完立刻看产物

> 排版没有玄学，只有取舍。

把[color:#b45309]重心[/color]放在一句话上。

—— 记下来，明天照着做一遍
```

### 稿 C：长文正文页（专测分页）

```markdown
# 长文分页回归样例

第一段正文，用来占掉封面之后的第一张卡。这一段刻意写得比较长，
好让测量台在这一页就接近装满，从而把第二段挤到下一页去。

## 第一节

第二节正文。段落之间的断行、字号与行距都会体现在产物上。

- 列表项甲
- 列表项乙

> 引用块跨页时不该被拦腰截断成孤零零一行。

---

## 第二节

第三节正文。上面那条 `---` 应当把这一节整体推到新的一张卡上。

| 项目 | 值 |
| --- | --- |
| 比例 | 3:4 |

最后一段，用来验证页尾不会被顶出去。
```

## 3. 已知预期现象（这些不是 bug，别报）

| 现象 | 真相 |
|---|---|
| 长文档打字明显卡 | W0 性能**故意没做**：每按一键全篇解析 3 次，150ms 防抖还被联动回调旁路。万字稿基本不可用。 |
| 微信/知乎复制后图片变 1×1 空白 | 有意为之：产物白名单只留 `http(s)` 与**位图** data URL，SVG data URL 换成透明占位——不静默删图。稿 A 特意不放图，测试图片请用真实网址。 |
| 拖分页边界的吸附有时不准 | jsdom 量不出块底边，只有真浏览器准；手感需要你判断"够不够用"。 |
| `release-check.sh` 转写端点红 | 与本模块无关，是 ASR 线的隐式模型下载。 |
| 字体分片 | 已判**不做**，见 `docs/MD_STUDIO.md` §9。 |

## 4. 发现问题时怎么贴

```
现象：一句话描述你看到什么
平台：微信 / 知乎 / 小红书 / 设计器 / 编辑器
稿子：稿 A / B / C，或贴出出问题的那几行 Markdown
步骤：从打开页面到出问题，一步不落
截图：最好带上画布缩放档位
```

**贴之前先问自己一句**："我期望的样子是什么？"——写下来。
如果期望说不清，那是讨论不是 bug；如果说得清，那是 bug。
按现在的判据层，定位会很快。
